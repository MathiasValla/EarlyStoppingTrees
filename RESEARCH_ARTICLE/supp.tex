\section{Implementation scope and notation}
\label{sec:supp_scope}

At a node, let \(n\) be the number of node samples, \(p\) the number of input
features, and \(k\) the number already known to be constant from ancestor
nodes.  The pre-scan feature budget is
\(m=\min(p-k,m_{\mathrm{try}})\).  The early-stopping methods use all features,
so \(m=p-k\); only the extremely randomized-tree (ERT) baselines vary
\(m_{\mathrm{try}}\).  Further constant features can be discovered during the
node scan.  For
feature \(j\), let \(D_j\leq n-1\) be the number of distinct adjacent-value
boundaries before leaf constraints, \(C_j\leq D_j\) the number of admissible
boundaries whose proxy gain is evaluated by an exact scan, and \(d_j\) the
number of continuously sampled thresholds.  A split gain is \emph{exact} when
it is computed from every sample at the node; this does not imply that every
candidate boundary was inspected.

Features are drawn without replacement from this budget in a randomized order.
A feature found constant at the current node is skipped without advancing the
number of encountered non-constant features and without reducing the
exploration target.  Whenever a feature is scanned exactly, its node samples are sorted by feature value and
its boundaries are processed in increasing value order.  Thus the methods use
a random feature order, not a random permutation of all feature--threshold
pairs.  For an exploration fraction \(f\), the target prefix contains

\[
 r=\max\{1,\min[m,\operatorname{round}(fm)]\}.
\]

The evaluated schedules are
\[
 f\in\left\{1/e,\;0.1,\;1/\log N_{\mathrm{data}},\;
 1/\sqrt{n_{\mathrm{node}}}\right\}.
\]
The logarithmic schedule is fixed from the
full dataset size, whereas the square-root schedule is recomputed at each
node.  For \(S\), the same fraction also controls the sampled-threshold budget.
For \(S^2\), \(f\) controls only the outer feature prefix and the inner
sampled-threshold fraction is fixed at \(1/e\).  These are not exploration
counts equal to \(n/e\), \(\log n\), or \(\sqrt n\).

The benchmark contains dense arrays without missing values and does not use
monotonic constraints.  The early-stopping helpers revert to exhaustive search
above 4096 input features.  The fallback was not activated: the retained
maximum is \(p=240\).

\section{Algorithms and implementation details}
\label{sec:supp_algorithms}

All returned splits are finalized from exact child impurities.  Ties use the
strict comparisons indicated below, and an exploration split is retained as a
fallback when no selection item is accepted.

\begin{suppalgorithm}{Algorithm S1: exhaustive CART and ERT baselines}
\textbf{Exhaustive CART.}
For each of the \(m\) randomized non-constant features, sort the node samples,
scan every admissible distinct boundary, and retain the largest proxy gain.
Finalize and return that split.

\smallskip
\textbf{ERT.}
For each of the \(m_{\mathrm{try}}\) selected non-constant features, obtain its
minimum and maximum without sorting, draw one threshold uniformly over that
range, partition the node, and evaluate the sampled split.  Return the best of
the sampled splits.  The four benchmark variants use
\(m_{\mathrm{try}}\in\{1,p/3,2p/3,p\}\).
\end{suppalgorithm}

\begin{suppalgorithm}{Algorithm S2: sampled-threshold, feature-stopping rule \(S(f)\)}
\textbf{Input:} node samples, \(m\), and exploration fraction \(f\).
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item Compute \(r\) from the pre-scan budget, draw features without replacement,
      and skip newly discovered constants without reducing \(r\).
\item For each of the first \(r\) features \(j\), sort the node samples, count
      \(D_j\), generate the vector of
      \(d_j=\max\{1,\operatorname{round}(fD_j)\}\) continuous thresholds once,
      sort it once, and evaluate it in a monotone batch.  Let \(\tau\) be the
      largest sampled gain over the prefix and retain its split as fallback.
\item For each later feature, perform one complete exact scan and obtain its
      best split with gain strictly above \(\tau\).  Return the first feature
      for which such a split exists.
\item If none exists, return the exploration fallback.
\end{enumerate}
The selection event is the first qualifying \emph{feature}; within that
feature the implementation obtains the best qualifying exact boundary.
\end{suppalgorithm}

\begin{suppalgorithm}{Algorithm S3: exact-feature rule \(S_{\mathrm{all}}(f)\)}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item Compute \(r\) from the pre-scan budget, draw features without replacement,
      and skip newly discovered constants without reducing \(r\).
\item Exactly scan every boundary on each of the first \(r\) features.  Set
      \(\tau\) to the largest featurewise maximum and retain its split.
\item Exactly scan each later feature.  Return the first feature whose exact
      maximum is strictly greater than \(\tau\).
\item If none is accepted, return the best exploration split.
\end{enumerate}
This is the closest implemented analogue of a secretary rule over randomized
feature scores, although its exploration fallback is not part of the classical
irrevocable model.
\end{suppalgorithm}

\begin{suppalgorithm}{Algorithm S4: calibration ablation \(S^2(f)\)}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item Compute the outer prefix length \(r\) from the pre-scan budget, draw
      features without replacement, and skip newly discovered constants without
      reducing \(r\).
\item On an exploration feature \(j\), draw
      \(d_j=\max\{1,\operatorname{round}(D_j/e)\}\) continuous thresholds and
      set an inner level to the largest sampled gain.
\item Scan every exact boundary on the same feature and retain its best split
      above the inner level, using the sampled split as fallback.  Update the
      outer level with this feature score.
\item On each selection feature, exactly scan for the best split above the
      outer level and return the first qualifying feature; otherwise return the
      best exploration split.
\end{enumerate}
The exploration feature is fully rescanned after sampling, so \(S^2\) is a
calibration ablation rather than a cheaper nested stopping rule.
\end{suppalgorithm}

\begin{suppalgorithm}{Algorithm S5: blockwise rank-inspired heuristic}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item Draw features without replacement and set
      \(b=\max\{1,\lfloor\sqrt n\rfloor\}\).
\item On each feature, exactly scan the value-ordered boundaries in contiguous
      blocks of \(b\), representing each completed block by its maximum gain.
\item Independently label each block ``exploration'' with probability \(f\).
      An exploration block can update \(\tau\); accept and return the first
      non-exploration block whose maximum is strictly above \(\tau\).
\item If no block is accepted, return the best exploration-block split.
\end{enumerate}
The benchmark uses \(f=1/e\).  This Bernoulli-block construction is
rank-inspired; it is not the published block-rank algorithm.
\end{suppalgorithm}

\begin{suppalgorithm}{Algorithm S6: two-pass prophet-style heuristic}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item In Pass 1, draw one threshold uniformly over every feature range without
      sorting, evaluate each sampled split, and set \(\tau\) to the largest
      valid sampled gain.
\item In Pass 2, replay the same feature order.  For each feature with a valid
      first-pass sample, sort and exactly scan all boundaries other than that
      sample's partition position.
\item Return the first feature having an exact split with gain at least
      \(\tau\); if none exists, return the best first-pass sample.
\end{enumerate}
The sample and replay use the same node and feature order, although the sampled
partition position is skipped during exact replay.  The
independence and irrevocability assumptions of single-sample prophet
inequalities therefore do not apply.
\end{suppalgorithm}

The implementation now uses a translation-invariant regression gain and the

\begin{suppalgorithm}{Algorithm S7: parametric rule \(S_{\mathrm{par}}\)}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\item Draw non-constant features without replacement and use the outer prefix
      \(r\) with \(f=1/e\).
\item On exploration feature \(j\), draw
      \(d_j=\min\{B,\max[1,\operatorname{round}(\rho D_j)]\}\), with
      \(B\leq256\), and compute the sampled proxy scores.
\item Fit a working law and compute its \(q\)-quantile: a moment-matched scaled
      noncentral \(\chi^2_1\) law for the centered regression gain, and a normal
      moment approximation for classification gain.  Scan exact boundaries in
      value order and retain the first score at least as large as this level.
\item Update the outer level with the retained exploration score.  On later
      features, return the first feature whose best exact score is strictly
      above the outer level; otherwise use the exploration fallback.
\end{enumerate}
For a fixed unweighted split under independent homoscedastic Gaussian errors,

\begin{align*}
 \frac{\Delta\mathrm{SSE}}{\sigma^2}
 &=\frac{n_Ln_R}{n\sigma^2}(\bar Y_L-\bar Y_R)^2,\\
 \frac{\Delta\mathrm{SSE}}{\sigma^2}
 &\sim\chi^2_1(\lambda),\qquad
 \lambda=\frac{n_Ln_R(\mu_L-\mu_R)^2}{n\sigma^2}.
\end{align*}

This fixed-split identity \cite{cochran1934quadratic} motivates the regression
working law.  It does not establish one common distribution across thresholds,
whose child sizes and mean contrasts differ.  The implementation therefore
uses the law to set a heuristic acceptance level, not as an exact calibration
claim.  It evaluates the between-child sum of squares directly,
\(n_Ln_R(\bar Y_L-\bar Y_R)^2/n\), so translating every response by a constant
does not change the mathematical score.  The classification normal law is also
a working approximation rather than a distributional theorem.
\end{suppalgorithm}

\subsection{Corrected \(S_{\mathrm{par}}\) screening}
\label{sec:supp_spar_results}

The corrected benchmark evaluated 20 configurations: five sampled-gain
budgets, \(B\in\{2,10,\operatorname{round}(\log N)\}\), or
\(\rho\in\{0.1,1/\sqrt N\}\) with \(B=256\), crossed with
\(q\in\{0.5,0.75,0.9,0.95\}\).  It used the same retained entries, fixed folds,
tree constraints, and seeds 42--141 as the main benchmark.  Predictive loss
and gain-evaluation effort are paired to exhaustive CART by entry and seed.

Wall-clock measurements are not reported for this screening.  The corrected
rule was run in August 2026 with NumPy 2.2.6, whereas the exhaustive reference
timings were collected in April 2026 with NumPy 1.26.4.  Although the hardware,
operating system, Python, scikit-learn, folds, and seeds match, the measurements
are not contemporaneous and do not support a valid runtime comparison.

After screening, \(S_{\mathrm{par}}(\rho=1/\sqrt N,q=0.9)\) was chosen for a
compact display because it lies on the internal \(S_{\mathrm{par}}\)
effort--loss frontier in all three tasks.  This choice is exploratory.  Values
in brackets are 95\% entry-bootstrap intervals.

The display configuration reduces recorded gain evaluations by 46.06\% in
regression and about 23\% in classification, but its regression loss is
11.19\%.  Across all 20 configurations, no point enters the full centroid
effort--loss frontier (Figure~\ref{fig:supp_spar_screening}).  Thus the
corrected experiment does not support \(S_{\mathrm{par}}\) as a competitive
effort--prediction compromise.

Three limitations govern this result.  First, the fixed-split Gaussian identity
does not give a common law across candidate thresholds, so the fitted
quantile remains heuristic.  Second, sampling, moment fitting, and exact replay
can offset reductions in gain evaluations.  Third, the configuration grid was
screened, so post-screening choices are not confirmatory.  Better
distributional models or calibration schemes remain open directions, but the
present evidence is negative.

\section{Node-level cost and recorded effort}
\label{sec:supp_complexity}

Let \(A_E\) denote exploration features, \(A_S\) exact-selection features
visited before stopping, \(h_j\leq C_j\) the exact boundaries scanned before an
\(S_{\mathrm{par}}\) threshold is met, and \(c_G\) the criterion-dependent cost
of a proxy-gain evaluation.  Table~\ref{tab:supp_complexity} gives fixed-node
upper bounds; the number of visited features is data dependent.

\begin{table*}[t]
\centering
\small
\caption{Fixed-node split-search work.}
\label{tab:supp_complexity}
\begin{tabular}{@{}p{0.13\textwidth}p{0.29\textwidth}p{0.50\textwidth}@{}}
\toprule
Method & Proxy-gain evaluations & Sorting, scanning, and other work \\
\midrule
Exhaustive CART & At most \(\sum_{j=1}^{m}C_j\) & Sort and scan every visited feature: worst case \(O(mn\log n+\sum_j C_jc_G)\). \\
ERT & At most \(m_{\mathrm{try}}\) & No sorting; one min/max pass and partition per feature: \(O(m_{\mathrm{try}}n+m_{\mathrm{try}}c_G)\). \\
\(S\) & \(\sum_{j\in A_E}d_j+\sum_{j\in A_S}C_j\) & Sort every inspected feature; count boundaries and batch-sort sampled thresholds in exploration; exact-scan selection features. \\
\(S_{\mathrm{all}}\) & \(\sum_{j\in A_E\cup A_S}C_j\) & Sort and exactly scan every inspected feature; worst case matches exhaustive order. \\
\(S^2\) & \(\sum_{j\in A_E}(d_j+C_j)+\sum_{j\in A_S}C_j\) & Sample and then fully rescan each exploration feature; the gain count can exceed exhaustive CART at the same node. \\
\(S_{\mathrm{par}}\) & \(\sum_{j\in A_E}(d_j+h_j)+\sum_{j\in A_S}C_j\) & Candidate count, sampled batch, fitted quantile, and exact replay on exploration features; the gain count can exceed exhaustive CART. \\
Blockwise & At most \(\sum_{j\in A_E\cup A_S}C_j\) & Sort and scan exact boundaries through the accepted block; worst case matches exhaustive order. \\
Prophet-style & At most \(m+\sum_{j=1}^{m}C_j\) & A min/max-and-partition pass over all features precedes sorted exact replay; the sampled partition position is skipped during the exact scan. \\
\bottomrule
\end{tabular}
\end{table*}

The splitter effort counter increments only for valid proxy-gain evaluations
after leaf-size and leaf-weight checks.  It excludes feature sorting,
candidate-count passes, min/max passes, random-vector generation and sorting,
partitioning, fitted-quantile calculations, memory traffic, and final split
application.  CART and ERT counts are reconstructed for successful internal
nodes, whereas early-stop counters also include failed split calls that produce
leaves.  Total-tree comparisons are therefore conservative diagnostics for
early stopping, and per-call normalization is not reported.  Gain evaluations
are therefore an interpretable search-effort
proxy, not a complete runtime model.  The fixed-node bounds also do not order
full-tree totals: methods can select different splits, create different
descendant topologies, and therefore make different numbers of later split
calls.

\section{Benchmark corpus and protocol}
\label{sec:supp_benchmark}

Every fold-specific fit grows one complete depth-limited tree: the selected
splitter is invoked recursively at each internal node by the same depth-first
builder, with \(\texttt{max\_depth}=20\) and common leaf and impurity settings.
Thus, each method--seed result averages five fitted trees, one per fold.  This
single-tree estimator design isolates within-node split search from bagging,
aggregation, tree count, and ensemble parallelism; no forest-level behavior is
inferred.

The retained PMLB corpus contains 113 regression entries and 122 classification
entries.  Gini and entropy use the same classification corpus.
Table~\ref{tab:supp_datasets} summarizes these entries.  The exact sharded
benchmark command was not retained, so the surviving run metadata do not show
whether the driver's optional \(np\) cap was disabled.  The largest retained product is
834,870.  The complete machine-readable repository inventory is:

Each estimator was evaluated by deterministic fivefold cross-validation:
integer \texttt{cv=5} gives unshuffled \texttt{KFold} for regression and
unshuffled \texttt{StratifiedKFold} for classification.  The folds are fixed
across methods and seeds.  The benchmark contains 100 seeded repetitions on those
fixed folds, using estimator seeds 42--141; each row stores fold-mean outcomes
for one dataset, method, and seed.  Regression performance is RMSE.
Classification performance is weighted F1 and is analyzed separately for Gini
and entropy.  The timing outcome is the mean estimator fit time returned by
\texttt{cross\_validate}; dataset loading, scoring,
serialization, and figure generation are outside that boundary.
Methods were evaluated in a fixed order with exhaustive CART first.  Pairing and
moving-block sensitivity analyses retain this order but cannot remove an
order-specific timing bias.

Gain evaluations are read from splitter counters for the early-stopping
methods, reconstructed from fitted trees and fold-specific training data for
exhaustive CART, and reconstructed as one sampled-threshold gain per selected
non-constant feature for ERT.  Timing and recorded effort therefore measure
different parts of the computation.

\section{Statistical analysis}
\label{sec:supp_inference}

\subsection{Pairing and estimands}

The PMLB entry is the outer experimental and inferential unit.  Seeds quantify
conditional randomization and timing variability within an entry; fixed folds
are neither treated as independent replicates nor resampled.  Every method is
paired with exhaustive CART by entry and seed before aggregation.  If
\(t_m\), \(g_m\), and \(L_m\) denote fit time, gain count, and predictive
performance for method \(m\), dataset-level points are medians over the complete
paired seed block.  Time saved is

\[
100\left[1-\frac{1}{\operatorname{median}(t_{\mathrm{CART}}/t_m)}\right],
\]

effort saved is \(100\operatorname{median}(1-g_m/g_{\mathrm{CART}})\), and
regression loss is
\(100\operatorname{median}(1-\mathrm{RMSE}_{\mathrm{CART}}/\mathrm{RMSE}_m)\).
Classification loss is
\(100\operatorname{median}(\mathrm{F1}_{\mathrm{CART}}-\mathrm{F1}_m)\) and is
reported in weighted-F1 percentage points, not as a relative percentage.  A
centroid is the equal-weight mean of entry-level medians; the cross-entry
median is a separate estimand.

Regression dataset \texttt{564\_fried} lacks recorded run 4.  Run 4 is removed
from the common paired block for every method and metric on that dataset, so
its summaries use 99 seeds without imputation.  Every other retained dataset
has 100 complete paired seeds.

\subsection{Paired hierarchical bootstrap}

Uncertainty is quantified by a paired two-stage nonparametric percentile
bootstrap with 10,000 replicates, 95\% intervals, and analysis seed 20260810.
Within each dataset, common seed identifiers are resampled jointly across all
methods and metrics.  At the outer level, datasets are resampled by identity
with replacement and receive equal weight; every repeated occurrence of a
dataset receives an independently selected within-dataset bootstrap draw.
Intervals are produced for dataset medians, equal-weight centroids,
cross-dataset medians, and dataset-level reliability probabilities.  Separate
within-dataset-only and between-dataset-only intervals are diagnostics; the
two-stage interval is the primary uncertainty summary.

The revision reanalysis designates exhaustive CART plus nine alternatives:
\(S(1/e)\), \(S^2(1/e)\), \(S_{\mathrm{all}}(1/e)\), the blockwise
rank-inspired method, the prophet-style method, and ERT with
\(m_{\mathrm{try}}\in\{1,p/3,2p/3,p\}\).  All other schedules are exploratory.
The corrected \(S_{\mathrm{par}}\) grid is screened separately in
Section~\ref{sec:supp_spar_results}; it is excluded from confirmatory tests
because its configurations were screened.  Its separate analysis reports only
paired predictive loss and gain-evaluation effort.

For the primary joint claim, an entry is successful only when its paired-seed
median time saving is positive and its paired-seed median loss is below the
task-specific margin: 1\% relative RMSE loss for regression and one weighted-F1
percentage point for classification.  An exact one-sided binomial test assesses

\[
H_0:\Pr(\text{time saved}>0\ \text{and loss}<1)\leq\tfrac12.
\]

Holm correction is applied across the nine alternatives within each task.
Margins 0.5 and 2.5 in the task-specific loss units are sensitivity analyses, with Holm correction across
all 18 method--margin hypotheses within each task; they are not labeled primary
confirmations.  Task--metric Friedman tests and two-sided paired Wilcoxon tests
against exhaustive CART, with Holm adjustment within each task--metric family,
provide complementary rank-based diagnostics.  Effect estimates and intervals
lead interpretation; adjusted \(p\)-values are secondary.

\subsection{Timing sensitivity and inferential scope}

Run-index correlations and linear drift summaries diagnose serial timing
patterns.  Circular moving-block bootstraps with block lengths 5 and 10 preserve
short-range run-order dependence when recomputing dataset medians and global
centroids.  This sensitivity analysis cannot remove bias from the fixed method
evaluation order within a benchmark run or reconstruct execution chronology
across independently scheduled shards.

The intervals condition on resampling this curated PMLB corpus and the recorded
estimator seeds.  PMLB is not a probability sample, folds were fixed, and only
fold means were stored.  The intervals therefore do not provide universal
coverage over all tabular problems or uncertainty over newly drawn train--test
partitions.  Marginal intervals over the exploratory method grid are not
simultaneous confidence bands.  The corrected \(S_{\mathrm{par}}\) rerun uses
the fixed retained corpus and therefore does not alter entry selection.

\section{Reproducibility record}
\label{sec:supp_reproducibility}

The benchmark metadata record Python 3.10.18, NumPy 1.26.4,
scikit-learn 1.7.2, treeple 0.10.3, and macOS 15.2 on ARM64 on a machine
reporting eight CPUs.  The benchmark host was independently verified as an
Apple M3 MacBook Air with 16~GB memory.  The metadata record five folds, seeds 42--141, the
estimator-only timing boundary, splitter-specific effort accounting, and the
treeple import path used during execution.  The exact sharded command was not
recorded, so disabling of the driver's optional product cap is not asserted.
The corrected \(S_{\mathrm{par}}\) campaign separately records NumPy 2.2.6,
the same Python and scikit-learn versions, the same host, all 20 configurations,
100 seeds, and complete coverage of the retained entries.

The inference program validates unique dataset--seed--method rows, requires all
ten confirmatory methods in every task, checks point estimates against the
figure aggregation, inventories incomplete paired blocks, and writes the
analysis environment and estimand definitions.  It also writes SHA-256 hashes
for every raw input CSV and for the audited benchmark, splitter, build,
analysis, and test sources.  The repository contains the benchmark and
analysis code, tests, dataset inventory, inferential tables, and figure and
table generators; the per-seed outputs are the manifest-verified input to the
revision analysis.
